# M1：日期级背景阈值的开发集比较协议（待确认）

日期：2026-09-26。项目组在[A2 事后失效诊断](stage9-a2-dev-failure-and-new-source-options.md)后选择 **M1**。本稿先固定实验口径，**尚未计算任何 M1 阈值或结果**。UCI 362 的[原日期划分](../results/stage9_uci362/proposed_split_manifest.json)保持不变；已查看过的测试集不进入 M1 拟合、比较或方法选择。

## 要回答的问题

[冻结原方法](stage9-a1-uci362-locked-results.md)在家庭酒／香蕉刺激的 5 分钟主终点上八通道检出 0/13；事后诊断发现训练背景 0.999 pooled 阈值以上的 129 个秒窗全属于 `id=65` 的同一日期。M1 检验：将各训练日期先压缩为一个背景高分位，再汇总日期，能否在不产生不可接受的背景触发的同时改善开发集检出？单日尾部集中是可检验的**阈值敏感性线索**，不先验断言它是污染或造成测试漏检的唯一原因。

## 预先固定的输入和算法

1. **仅在读取时保留训练和验证 ID。**校验原包及划分 SHA；训练 57 条、验证 21 条，分别为 34／12 个日期。现有测试 ID 不载入结果数组，不输出任何新测试分数。原 ZIP、原划分和第一次运行记录留原位；新输出独立存放。
2. 一秒取中位、八通道有效性、本文件 `[-3600,-2700)` s 事前基线、至少 600 个有效基线秒、训练背景窗 `[-2700,-300)` s、尺度向量 `s_j`、主分数 `m(t)=median_j |R_j(t)-c_{ej}|/s_j` 均严格取自[冻结运行器](../scripts/run_stage9_uci362_locked.py)及其训练参数。**只替换阈值的聚合方法**；不得为提升检出改变尺度、分数、前 5 分钟终点、缺测或三秒 G2 门控。
3. 对每个有有效训练背景秒窗的日期 `d`，汇总该日全部可校准训练文件的背景分数，计算 `Q_d = quantile(m_d, 0.999)`，使用 NumPy 默认线性插值。日期内完整记录不随机分窗，同日文件只贡献该日的一个 `Q_d`；文件时间戳无法精确去重，若同日片段重叠，仍如实说明其对**日内**分位的可能影响。预计有效背景日期 33 个，实际数必须在结果中核对。
4. **M1 主阈值**事先取 `T_M1=quantile({Q_d}, 0.75)`。将日期高分位的 0.50 和 0.90 聚合分别作为**敏感性分析**；冻结 pooled 秒窗 0.999 阈值 `22.082579798983733` 作为原基线。上述四个阈值均只用训练集背景计算；不得依照验证检出率再增加网格、挑阈值或改变聚合分位。0.75 是针对“单个日期控制全体秒窗极端尾部”的可解释折中，**不是由现场容忍误报率推导的安全阈值**。
5. 用四个阈值分别在训练／验证日期运行原三秒 G2 程序。阳性仅酒／香蕉人为刺激，必须为 `time≥0` 发源且在 `time≤300 s` 完成的事件；缺基线或刺激后 5 分钟有效秒不足 120 的条目标 `unknown`。纯背景日期定义、有效观察小时、同日不重复计时、阳性刺激前时段单列等沿用[原协议](stage9-a1-uci362-source-audit-and-protocol.md)。原 R1 结果只作为仓库中已有的参照，不用来为 M1 挑阈值。

## 固定输出和判断条件

| 指标 | 报告方式 | 不允许的解释 |
| --- | --- | --- |
| 训练／验证刺激 | 总条数、可评价、`unknown`；按酒／香蕉给出 5 分钟内 G2 分子／分母、已检出者名义延迟 | 酒／香蕉检出率不能说成 CO／CH4 泄漏检出率或事故提前量 |
| 训练／验证纯背景 | 每个日期的首次触发、G2 次数、实际可观测小时；汇总触发日期数和总小时 | 6／2 个纯背景日期不足以证明现场长期低误报 |
| 有刺激文件的刺激前段 | 单独列 G2 数和记录数；不与纯背景日期合并成独立阴性小时 | 可能含同日残留与其它家庭气味 |
| 阈值敏感性 | 四个固定阈值、每日期 `Q_d`、`id=65` 所在日期的影响；**仅诊断**地去掉整个 `09-03-15` 日重算阈值，不将其当新主结果 | 不能因为删除该日结果好就正式剔除它 |

判读以 **M1 主阈值**为准。若主阈值提高开发集检出但导致纯背景日期频繁触发，须同时呈现两面结果；若完全未改善，也保留失败结果。0.50／0.90 仅说明权衡曲线，不择优替换主阈值。验证日期只作为已参与本项目流程的**开发期留出**，由于 M1 是在查看过原验证和测试结果后提出的，验证改善只能称探索性证据，不能恢复盲测资格。不得把原测试 0/13 更新成 M1 测试成绩。
