# 小型公开数据补查与研究范围建议

日期：2026-09-26。项目组要求停止下载大型工业巡检归档，优先使用可核验的小型数据。如果没有同现场人员、气体和事故真值，收缩实验主张。本阶段只核查来源与字段，不新增模型结果。

## 已取得的新增来源

[RoboFusion-Dataset](https://github.com/Amr-Khamis-84/RoboFusion-Dataset) 的 `real_data/Real_Dataset_Normal_Hazard_12 Days_ 3 Hazards.xlsx` 已从发布者 GitHub 仓库取得（来源提交 `d3907eda585cf202fc00c462b550d2512d5b9e6f`），原件保存在忽略的 `data/raw/robofusion_12d/`，不推送原始数据。文件 5,598,616 字节，SHA-256 `09c32cc594e7ae74e62e4e583623e320e9ed04e186f0987c6d5638e6cba0a428`；只读复核程序为 [`audit_new_multimodal_sources.py`](../scripts/audit_new_multimodal_sources.py)，结果为 [`robofusion_12d_audit.json`](../results/stage9_new_sources/robofusion_12d_audit.json)。上游仓库许可证为 CC0；论文引用应按最终发表版本核对作者和刊名。

| 核对项 | 公开文件的实际内容 | 解释限制 |
| --- | --- | --- |
| 规模与采样 | 2025-04-10 至 04-21；69,120 行；4 个节点各 17,280 行；每分钟同步 1 行 | 公开的是 12 天样本；作者所述的 180 天完整记录未公开于仓库，不能把两者当成同一文件 |
| 字段 | `T1,H%,P,AL,T2,Dust,MQ2,MQ4,MQ5,MQ7,MQ8,MQ135`，另有时间、节点、`Condition` 和 `Status` | MQ 通道为传感器响应；本文件没有可直接当作校准 CO/CH4 浓度的物种浓度列 |
| 事件 | `Hazard_1` 120 分钟、`Hazard_2` 73 分钟、`Hazard_3` 60 分钟；同一事件标签复制到 4 节点 | 作者将 `Hazard_3` 解释为受控气体泄漏，**仅 1 次事件**，240 行不是 240 次泄漏；没有独立操作日志可复核释放精确起点 |
| 数据处理 | `Original` 42,705 行、`Interpolation` 26,415 行（约 38.2%） | 应报告插值影响，不可把每行视为独立观测；无独立现场事故真值 |
| 视觉/空间 | 无同期视频、人员坐标、节点坐标 | 不能验证“人员靠近泄漏点”的真实配对风险，也不能证明视觉+气体实测交叉验证 |

该文件可用于**同期环境传感器数据的质量审计和受控事件个案可视化**。三种受控事件各只有一次，不足以独立训练/检验可泛化的三类事故识别、气体泄漏提前预测或四级事故风险分类。其原始 README 写有 `sample_preview.csv`，实际公开的是上述 xlsx；本报告以实际文件为准。

## 建议的范围收缩

1. **气体实证**：UCI 309 用于受控供气后的异常检测；已选 B2-B 的煤矿序列作为**候选**未来测点持续越限预报任务，须先确认[开发期协议](stage9-b2-b-development-eda-and-protocol.md)，才可构造预测窗和拟合模型。两项任务要分开计分，不能把 UCI 309 的供气后检测写成事故前预报，也不能把煤矿越限写成焦化事故预测。RoboFusion 仅用于四节点同期环境数据及受控事件**个案**的处理流程验证。
2. **视觉支线**：保留现有 Bonn 人员二维框与深度接口结果，空间危险区采用明示的虚拟区域/仿真轨迹；仅声明模块级验证。气体与人员组合风险最多用明确标注为仿真的场景重放，不能报告为真实同步多源融合效果。
3. **删去当前论文实证承诺**：车辆违规、烟雾遮挡识别、液体泄漏/积液、液位、粉尘超标和 Jetson 性能实测；这些保留在申报书目标的差距表或未来扩展，不写成已经完成。D435 与 Jetson 是拟部署器件，未开展采集或实机测试。
4. **题目口径**：暂用“面向焦化园区典型风险场景的气体异常预警与人员空间风险协同方法”作工作标题；摘要须说明气体/视觉分别验证、联合重放为仿真。若 B2 留出结果不能支持预测能力，则不得保留“提前预测”主张，最终标题须与实证结论一致。

下一步是请项目组确认 **B2-B 的精确标签与评价协议**；随后才构造因果预测窗、在开发/选择期比较基线，最后进行冻结留出评价。不为补齐申报书每个场景继续找无标签的杂项数据。上述范围是建议；实际题目和论文主张须在后续阶段由项目组审定。
