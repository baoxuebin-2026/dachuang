## 1. 方法与事实边界

- [UCI 322](https://archive.ics.uci.edu/dataset/322/gas+sensor+array+under+dynamic+gas+mixtures)：乙烯＋CO、乙烯＋甲烷各**一条**气室长时间序列，目标是“气源设定值由 0 变正之后，传感器是否给出变化报警”。推理接口只接收 16 路传感器；气源设定、实验时间和实验区段只在离线标注和诊断时使用。训练 `[3000,12000)`、验证 `[12300,24000)`、测试 `[24300,39000)` s；块间 300 s 隔离。正例须前 60 s 双气零设定且目标气后续至少维持 60 s；只在两气零设定累计 120 s 后统计保守阴性；但零设定并不证明气室已清空残留气体。
- B0：训练区段事先选定的**一条通道**的标准化绝对偏离；B1：**16 通道**偏离的中位数。主阈值各在训练双零区段取 0.99 分位，连续 3 个完整 1 s 窗才报警；0.995 分位为冻结的敏感性分析。两条气体文件分别训练阈值。测试只运行一次，漏检未删除；事件前已有报警或已开始累计的证据不算作新检出。B0 在训练所选通道下标 CO=1、甲烷=5；不含“CO／甲烷气体种类分类器”。
- [SB112](https://zenodo.org/records/6616632)：每个仪器通道**单独**用 3 月 8 日无人工触发数据定上侧分位阈值，9 日验证，10 日保留阴性测试；主规则 0.99 分位且 2 个相邻有效观测超阈值。时间间隔 >60 s 中断状态且不算进覆盖时长，近 300 s 内同一运行段的反复触发合并为一个事件。3 月 11 日作者仅给“当日曾进行近距离刺激”，没有准确开始秒；本次只查读数范围，不计检测时延或召回。

## 2. UCI 322 留出时段结果（实验室气源设定变化）

下表全部采用**冻结的 0.99 阈值**，延迟是已检出事件自气源指令变正开始到完成秒窗报警的正向时间。文件内大量时段相关、设定程序可能重复：`14／14` 是**同一次 CO 气室连续运行中的 14 段**，不是 14 次独立焦化厂事故。完整结果见[逐方法三块汇总](../results/stage7_a/uci322_summary.csv)和[CO 逐起点](../results/stage7_a/uci322_ethylene_CO_events.csv)／[甲烷逐起点](../results/stage7_a/uci322_ethylene_methane_events.csv)。

| 气体条件 | 方法 | 测试块 60 s 内新检出／合格起点 | 已检出延迟中位数及范围 | 测试块合格双零时长 | 其中新发报警 |
| --- | --- | ---: | --- | ---: | ---: |
| 乙烯＋CO | B0 单通道 | **0／14** | 无已检出事件 | 0.246 h，约 14.8 min | 0 |
| 乙烯＋CO | B1 多通道 | **14／14** | 21.99 s；20.99–24.99 s | 同一段 0.246 h | 0 |
| 乙烯＋甲烷 | B0 单通道 | **13／13** | 20.99 s；19.99–21.99 s | 0.461 h，约 27.6 min | 0 |
| 乙烯＋甲烷 | B1 多通道 | **13／13** | 23.99 s；21.99–32.99 s | 同一段 0.461 h | 0 |

CO 的单通道规则在训练区段曾检出 4／5 次，到验证与测试变为 **0／7、0／14**；多通道在 CO 的验证和测试为 **7／7、14／14**。这表明本次单通道选取对后续时段不稳定；但甲烷的 B0 测试同样 13／13，且检出中位延迟比 B1 更短。因此只能说**在本次 CO 试验的这套训练和时间切分下，多通道规则优于已冻结的这条单通道**；不能说它在所有气体、场地和设备上更好。改用已预列的 0.995 分位时，这四项测试检出数未变；阈值依然不能改成法律或工业报警线。

“0 个新发双零报警”的分母对 CO **不足 15 min**、对甲烷 **不足 28 min**，且双零区段来自同一装置的间歇运行；不支持“工业场地零误报”或有把握的小时误报上界。真实传感器也可能响应乙烯或器件漂移；**本轮并未评价乙烯单独设定区段是否报警**。对本次测试入组起点进行只读源核验时，其起点处乙烯设定为 0，但这不能证明整个序列具备 CO／甲烷种类特异性。

另存[时钟伪基线](../results/stage7_a/uci322_clock_only_diagnostic.csv)：只根据训练设定值选择一个 200 s 时钟相位，完全不读取传感器，它在留出块碰中 CO **8／14**、甲烷 **3／13** 个 60 s 时段，同时在合格双零区段分别脉冲 **3／8 次**。这个模型以实验程序标签选择相位，**不能部署**；其偶然命中提醒：UCI 322 含有重复设定片段，不能拿 B1 的高检出率断言“已经消除了程序捷径”。B1 的实际输入确实不含时钟与设定值，但单靠这一点不能证明跨独立现场泛化。

## 3. SB112 本机无人工触发日结果

主规则按各自 3 月 8 日训练数据确定阈值；以下均为 **3 月 10 日保留日**，时间分母仅累计实际有相邻有效观测的分钟。校验日 3 月 9 日烟雾通道另有 **2 次／14.054 h**；其他三个通道当天 0 次。逐日、阈值敏感性和实际覆盖见[全表](../results/stage7_a/sb112_summary.csv)、[逐报警时间](../results/stage7_a/sb112_episodes.csv)。

| 传感器 | 10 日有效覆盖 | 背景报警事件 | 事件／覆盖小时 |
| --- | ---: | ---: | ---: |
| CO | 23.996 h | 0 | 0 |
| CNG | 23.997 h | 0 | 0 |
| LPG | 23.997 h | 0 | 0 |
| 烟雾 | 23.978 h | **6** | **0.250** |

烟雾通道主规则共有 24 次原始“重新进入报警”，按预定 300 s 去抖合并为 6 个事件；已预列的更高 0.995 分位＋连续 3 观测方案在测试日仍有 **3 次／23.978 h**。不能在看到结果后偷偷改以敏感性方案为主结果。发布者称 8–10 日未施加物理刺激，但无人逐秒标注外部环境，所以这 6 个是**无人工触发期间的背景报警**，尚不等价于经过人工核实的 6 次“虚假事故”。CO/CNG/LPG 的 0 是这三路、这一天、这套本机阈值下的观测值，不证明安全预警器有高灵敏度。

SB112 发布数据中的 11 日 LPG 列虽然标 `ppm`，本次文件最大值达到 **1,158,225 ppm**（大于纯气体的百万 ppm），提示原表的读数／校准或饱和状态不能不加核实就作为有物理意义的工业浓度。本研究没有用 11 日选择阈值或计算检出率；此前提出“刺激日定性查看”还缺**具体刺激时间**和仪器校准信息，不能将极端数值写成真实泄漏浓度。

## 4. 复现、结论与下一决策

运行文件中的配置 SHA、代码 SHA、数据 SHA 和环境版本，与[结果登记](../registries/result_registry.csv)互相引用。源数据放 `data/raw/`，不入 Git；报表、逐事件和参数随仓库提交。正式计算只需：

```bash
python scripts/download_data.py 322
python -m pip install -r requirements-eda.txt -r requirements-source-audit.txt
python -m unittest discover -s tests -p test_stage7_a_boundaries.py -v
python scripts/run_stage7_a.py
```

复现 SB112 时，还要从[Zenodo 原记录](https://zenodo.org/records/6616632)下载四个同名 XLSX 到 `data/raw/sb112_zenodo_6616632/`；程序未打包原始 XLSX，运行元数据会记录每个文件 SHA。TADI 虽已审计，未参与这次模型计算。

**目前可写的结论**：在两条 UCI 322 气室序列各自的未来时间块中，固定多通道方法对入组目标气设定变化能够给出实验室级释放后报警；单通道对 CO 跨块失败；另一套 SB112 装置展示无人工触发时烟雾报警会出现、且报告报警时需要明确时间分母。**仍不能证明**焦化园区实际事故识别率、多源真实时空融合准确率、事前预报能力、D435 视觉检测或 Jetson 实测实时性。原申报书的视觉烟雾遮挡、积液、车辆违规、操作违规和粉尘研究仍待完成或结题时如实解释差异。
