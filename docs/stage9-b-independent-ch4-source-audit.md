# B 阶段：有独立释放真值的甲烷来源核查与路线决策

日期：2026-09-26。项目组选 B：在 M1 开发实验后寻找另一来源，先核查数据，再决定是否改变研究问题。本报告只审计来源与可评价性，**没有拟合模型、计算检测成绩或重新打开旧测试集**。[煤矿与混合气审计脚本](../scripts/audit_stage9_b_sources.py)及其[煤矿](../results/stage9_b_sources/mine_source_audit.json)、[混合气](../results/stage9_b_sources/pipeline_source_audit.json)输出；[DLQ 审计脚本](../scripts/audit_stage9_b_dlq_source.py)及[输出](../results/stage9_b_sources/dlq_source_audit.json)。原始数据放在被 Git 忽略的 `data/raw/` 或原作者仓库，不随本仓库分发。

## 当前卡点

现有 UCI 362 是酒/香蕉气味实验，其预登记外测结果很差；M1 对日期均衡阈值的开发分析并未解决焦化 CO/甲烷的外部真实性。下一来源最好有**独立于传感器响应的事件起止记录，以及无释放对照**。只靠传感器浓度越限生成的标签，可用于“未来越限预测”，却不能验证真实泄漏开始的检出率。

## 候选方案与建议

| 下一主线 | 可回答的问题 | 优点 | 实验/论文风险及与申报书的对应 |
| --- | --- | --- | --- |
| **B1：DLQ 受控释放 + 多点甲烷/气象事件识别（推荐先设计协议）** | 在独立释放时序下，环境甲烷多点观测比单点阈值能否更稳地识别放气开始并控制无释放期间误报？ | 真实独立起止、真实连续阴性、多点/时序；易定义延迟与误报单位，适合多源交叉验证。 | 只有 7 天 17 事件；微量排放浓度不是安全危险等级，不含 CO，原作者已有检测算法；需用按日期分组、简单单点和作者方法作基线，不能承诺显著提升，也不能称直接焦化预警验证。视觉/CO 用独立模块或设计场景，不伪造同场融合。 |
| B2：煤矿现场多变量甲烷未来越限预测 | 以过去监测预测未来 3–6 分钟目标点首次越限，衡量及时性与误报。 | 大样本、物理安全场景、环境协变量，多日期外推可检验。 | 越限真值来自目标传感器，**不是泄漏发生**；井下工况迁移到焦化有限、既有研究竞争强。视觉和 CO 不能在同一实测样本中验证。 |
| B3：混合气响应识别主线 | CH4、CO、H2S 混合物下多通道辨识和抗串扰。 | 申报书 CO/可燃气体吻合度最高，可开展组级留出。 | 只有一个独立全零试次、固定供气时间；不能支持长期误报和真实提前预警。论文问题需收缩为受控辨识。 |

**推荐 B1 的“协议设计”作为下阶段**，因为它首次提供“浓度输入以外”的事件真值和无释放对照，能检验原项目“单点→交叉验证→预警”的可验证部分。此建议不等于 B1 方法已有效。应先固定每日期留出、禁止泄露的字段、放气开始的时间容差、无释放误报（每小时及每段）与漏报定义，并审查作者已有基线及响应传播延迟；之后才开发算法。旧 UCI 362 测试已见过，任何修改后的成绩只能称探索性复用，不能把 DLQ 称同传感器盲测。矿井可作为**另一个预测任务**而非 B1 的分数合并；混合气只用于受控气种辅助实验。

申报书设备定位仍为**拟部署架构**：D435 提供人员相对危险区位置，Jetson 是可行性讨论中的边缘端，CO/甲烷等是拟接入感知端；本轮所有真实实测均来自第三方不同场地。论文对“焦化园区分级风险”“CO+人员同时实测”“D435/Jetson 实验验证”的结论都不能由这些源直接推出，后续需要单独模型定义、仿真标记或实际采集；发表口径应先限定为方法和受控场景实验。

## 【需要人类决策】

是否选择 **B1：先为 DLQ 受控释放数据制定可冻结的事件识别/交叉验证协议**？若优先研究真正危险浓度的未来越限，选 B2；若优先保持 CO+CH4 双气体，接受只研究受控响应，选 B3。决定前不继续建模。
