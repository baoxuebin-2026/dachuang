# 阶段 8 / V1-A：RGB-D 数据取得核验与待确认的视觉实验协议

记录日期：2026-09-25。项目组已选定 [V1 候选 A](stage8-v1-rgbd-source-audit.md)：用公开人员画面验证“2D 人员证据—有效深度—模拟区域规则”的局部接口。**本文是数据取得核验及预先提交的协议；没有下载原始 RGB-D 帧，没有执行人员检测、测距或越界性能实验。**

**取得路线**：先在能访问官网的网络获取 LIRIS D1 的一份**包含连续灰度帧和对应原始深度帧的原始归档**、相应 XML 与相机标定／深度换算资料；不必先拿全量。官网索引列出 D1 训练灰度＋深度约 2.8 GB，体量应按实际下载页面与归档核准。由团队保存在 `data/raw/` 本地或受控存储，不提交原始大包到 Git。记录官方 URL、取得日期、原始文件名、大小、SHA-256、引用要求和许可文本／使用条件；如网站只提供整包，先核实空间再下载。研究助理能取得并核验时自行办理；**当前网络不能证明该下载已成功**。若由成员取得，请在可共享位置提供*原始归档、相应 XML、标定资料与官网使用条件截图／存档*；不要仅截取转换后的几张图，否则无法核对时序与尺度。

## 2. 开始抽样的硬门槛

1. 检查灰度（或彩色）与**原始**深度图可读、尺寸／位深、帧号与时间对应；执行官方标定规定的坐标映射和一帧偏移核验，不把灰度像素坐标直接当深度像素坐标。
2. 检查深度原始编码、无效值、换算尺度和相机内参／外参。若只能得到伪彩深度，或无法确认米制尺度，最多展示“深度字段可用性”，不报告以米计的 3D 点或 1 m 规则。
3. 查看 XML 类别和框语义。LIRIS 是**活动框**；用于人员检出评价的独立人工人员框须另建标注，并留下抽样编号、标注说明、人员归属和复核记录。
4. 对照官方使用条件，确认本项目的研究、图片在论文中展示和是否允许再分发；条件不明则原始帧不推送公开仓库。
5. 核对独立序列数量、人员可见程度、远近和遮挡，若不足以支持留出序列或相应分层，只做探索性案例，不给泛化分数。

**任一关键门槛失败就停在数据审查节点**，提交失败证据与可行替代；不靠构造人员框、虚拟焦化现场或假标定填补。

## 3. 拟冻结的抽样与标注协议（数据核验成功后再确认）

- **实验单位**：相互独立的官方视频序列／拍摄会话；列出所有序列 ID、长度、可读帧数、画面人物与缺失情况。先按序列划训练／开发／测试，**相邻帧不能分到不同集合**；序列数过少则只做案例分析。
- **抽样候选**：为本科工作量，建议从至少两个独立序列中按预先写定的固定时间间隔抽帧，并额外以事先定义的“遮挡／边缘／深度缺失”规则抽取困难帧。初始目标约 120–200 帧，用实得人员数、连续性和独立序列数重新确定可行样本量；列出所有纳入及排除帧，困难帧单独分层，不能挑算法成功帧。种子、时间间隔、实际数、分层依据在评估前冻结。
- **人工真值**：在原灰度画面上为可见人员逐个画 2D 框（含可见部分、严重遮挡的统一定义）；两人对一部分样本独立复核，分歧仲裁并保留原始记录；标注员不查看待评算法结果或模拟区域是否报警。动作框仅用来定位含活动的序列，**不用于打分**。
- **方法分开**：先使用人工人员框作为 *oracle* 输入验证深度匹配、三维点和模拟区域规则；若另引入一个预训练人员检测器，先核对模型权重与许可，锁定模型、阈值与版本，再以人工 2D 框评价检测。*Oracle 投影效果不能写成模型检测准确率*。
- **深度点与区域**：对灰度框按官方标定映射到深度画面，在人物框内预定义的中央躯干候选区域统计有效深度；有效比例低、深度跳变明显或越出量程时输出“位置未知”。用固定的有效深度中位数得到相机坐标 (Z)，标定齐全时再用 (X=(u-c_x)Z/f_x,\;Y=(v-c_y)Z/f_y)（必要时采用官方外参）；不能假定框中心落在人体表面。若要与地面边界的距离，需要地面平面及相机相对地面的位姿；没有这些条件时仅使用**相机坐标的虚拟体积区域**，明确研究者设定，拒绝写作真实园区越界。
- **评价与对照**：记录独立序列及总帧数、带人帧数、人员框数、2D 检测 precision／recall（仅有实际检测器才可计算）、匹配到有效深度的比例、位置未知比例、深度结果对采样窗口与缺值处理的敏感性。对同一帧分别报告“仅 2D 模拟画面区域”与“深度支持的相机坐标虚拟区域”的规则响应差异；**虚拟区域由规则生成，不能将与自身规则的一致率当真实事故识别率**。无独立三维位置真值，不计算三维位置 RMSE；无真实危险区真值，不计算真实越界 F1。
- **可复现记录**：原文件哈希、图像／深度对齐参数、标注版本、序列级划分清单、所有研究者设定区域参数、模型权重与阈值、脚本运行 ID、排除原因及每个结果适用范围。若制作图表，遵守[项目工作流](research-workflow.md)的计算和绘图分离及证据登记。

## 4. 面向申报书的结论边界

此验证最多支持“公开 Kinect RGB-D 序列中的人员 2D 证据和深度投影，可以按研究者设定区域生成带缺失标记的空间输入”。D435 和 Jetson 均只写作拟部署；公开人员数据与 UCI 气体来自不同实验、不同时间和地点，组合只能做**规则级仿真／接口试验**，不能写“焦化厂同步多源传感实测”或“D435 测距已验证”。即使取得 RGB-D 数据，申报书中烟雾、积液和设备性能等项目仍未完成，见[承诺表](commitments.md)。
